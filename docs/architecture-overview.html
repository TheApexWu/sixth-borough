Sixth Borough

Cultural memory infrastructure that runs on the community's own hardware.

The Product

A 3D time machine for every building in New York City. 1,082,831 structures across all five boroughs, extruded to real LiDAR roof heights, scrubbing from 1700 to 2026. Click any building for a forensic biography generated by a 30-billion-parameter language model running locally. No cloud. No internet at runtime.

Ghost buildings remember what the city demolished: the Twin Towers rise and vanish, Penn Station disappears, 117 Cross-Bronx tenements collapse year by year as Robert Moses displaces 60,000 people. 750 archival photos from the NYPL Milstein Division are pinned to the map. Immigration flows animate across centuries.

Two Renderers, One Data Spine

The core engineering decision: build two rendering paths that consume identical data (building polygons, landmarks, ghost manifests, cultural content). The browser demo proves the concept works. The native renderer is where it becomes a real product.

Browser Demo SHIPPED

deck.gl 9.1.4 + MapLibre GL + GSAP. Single index.html, zero build step.

  • 45K+ building polygons per borough, extruded on a flat map plane
  • Time-gated construction/demolition with 8 era color bands
  • Immigration particle simulation (800 concurrent particles, 5 shape modes)
  • CPU Sobel sketch overlay (PS2 aesthetic, single-frame capture)
  • Guided tour with GSAP-animated cutscenes and radial burn transitions
  • NYPL photo pins, demolished landmark layer, borough toggles
  • Runs on any laptop with a browser

Limitations

  • Flat map plane (z=0), no real 3D depth or lighting
  • Ghost buildings are procedural rectangles, not authored geometry
  • Sketch overlay is a frozen CPU screenshot, drifts on pan
  • No materials, no shadows (material: false for performance)
  • Outer boroughs disabled by default for laptop perf
Native Renderer IN PROGRESS

Bevy 0.18.1 + wgpu. Rust. Targets the DGX Spark natively.

  • Real 3D scene graph: camera, directional lighting, shadows
  • ECS architecture: each ghost is a Bevy entity with coordinate, era window, niche tags
  • Artist-authored .glb meshes for demolished buildings (Blender pipeline)
  • Sibling manifest pattern: each asset family has its own MANIFEST.json
  • PS2 post-process as GPU shaders (Sobel, vignette, palette quantization)
  • Live narration from Nemotron 30B in the same unified memory address space
  • WASM compile target for web fallback

Current State

  • Renderer scaffolding, ECS data model, ghost manifest loader: built
  • Building geometry, timeline system, post-process shaders: not yet integrated
  • Asset pipeline designed, awaiting authored .glb ghost meshes

Why Rust + Bevy, Not Just WebGL

The browser demo renders buildings as extruded polygons on a flat plane. That works for proving 300 years of NYC history fit in 60 MB. It does not work for what demolished buildings actually need to be: authored 3D objects with real geometry, lit in a proper scene, casting shadows on the streets they once occupied.

The Rust renderer exists because ghost buildings deserve volume, not just footprint extrusion. A Blender artist models Penn Station as a low-poly mesh. The manifest loader spawns it as a Bevy entity at the correct coordinates with an era window component. When the year slider crosses 1963, the entity fades. That is fundamentally different from drawing a rectangle on a map and giving it a height value.

Running natively on the GB10's Blackwell GPU also means the renderer, the 30B language model, and the building geometry all share 128 GB of unified memory with zero PCIe copies. The browser version has to work within WebGL2 constraints and whatever VRAM the user's laptop has. The native version has access to the full chip.
