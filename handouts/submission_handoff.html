Sixth Borough
Submission Description
New York has five boroughs you can walk through. The sixth one only exists in this box. Sixth Borough is a 3D map of every building in NYC, 1.05 million structures extruded to real LiDAR roof heights, scrubbable year by year from 1700 to 2026. Drag the slider and watch the Twin Towers rise in 1970 and vanish on September 11. Watch the Cross-Bronx Expressway hollow out 159 blocks between 1948 and 1972. Click any building and a 30-billion-parameter NVIDIA Nemotron model, running on the GN100 with the ethernet cable on the floor, writes a footnoted forensic biography from four public NYC datasets. No cloud. No speculation. No internet at runtime. The demo traces one chain: Robert Moses displaced 60,000 South Bronx families onto Sedgwick Avenue, where the crowding created the rec room party scene, where DJ Kool Herc invented hip-hop on August 11, 1973. Cultural memory is what survives the bulldozer. We built the archive that proves it, on hardware the community can own for $3,000.

Bounty Description
NYC's right-to-counsel expansion in 2022 guaranteed legal representation for 20,000 new tenant cases per year. Every one of those cases needs a building history: ownership chain, violation records, demolition context, displacement patterns. Today that takes a paralegal 6 hours pulling from 8 separate city databases. At $100/hr that is $600 per case, $12M/yr of redundant labor across the legal aid system. Sixth Borough assembles the same dossier in 30 seconds from public records for $500/mo per attorney seat. The reason this has to run locally is not ideology. Rule 1.6 of the NY Rules of Professional Conduct requires client confidentiality. Tenant attorneys legally cannot upload privileged case files to OpenAI or Anthropic. The same constraint applies to insurance underwriters running proprietary risk models and REIT analysts doing acquisition due diligence. Three compliance-locked buyer segments, one engine, one $3,000 box the firm owns outright. 100 attorneys at $500/mo = $600K ARR year one, REIT and insurance in NYC = $5M year two, five cities = $25M year three.

Models Used
NVIDIA Nemotron-3 Nano 30B (A3B variant), quantized to Q8_K_XL GGUF format. Served via llama-server (llama.cpp) with all 99 layers offloaded to GPU. Used for generating building biographical narratives from structured context (building metadata, census data, cultural event timelines). 29 tok/sec sustained inference, 11ms cache hit latency.
Tools Used
llama.cpp (llama-server), CUDA 12.8, cuBLAS, Python FastAPI, deck.gl, maplibre-gl

Acer GN100 Questions
How was Acer GN100 Leveraged?
Everything runs on it with no internet. 128 GB unified memory holds the 30B model (38 GB), 262 MB building data, orchestrator, and renderer in one address space. Demo ends by pulling the ethernet cable and clicking another building. Biography generates with the cable on the floor.
Were there any capabilities of the device that supported your build in a unique way?
Yes. The 128 GB unified memory let us load a 30B parameter model (Nemotron-3 Nano Q8_K_XL) with all 99 layers on GPU while simultaneously serving 231 MB of building geometry data. On any discrete-GPU setup we'd be swapping between model weights and data. Unified memory meant we could run inference and serve a million-building map from the same box with zero contention. That's the entire thesis of the project: cultural memory infrastructure that fits in one room with no cloud dependency.
How was it building with local inference/compute? (1-10)
8. The raw capability is exceptional. Loading a 30B model with full GPU offload on a single desktop-class box is something we couldn't do 18 months ago without a multi-GPU rig. The inference speed was production-grade for our use case. Cons: first-boot setup (driver verification, confirming CUDA paths, figuring out the right llama.cpp flags for this specific chip) took trial and error with limited documentation for the GB10 specifically.
Would you recommend the Acer GN100? (1-10)
8. Yes for any project where data sovereignty or offline operation matters. The unified memory model is genuinely different from anything else at this price point. Would especially recommend for teams working with sensitive data (medical, legal, government) who can't send inference requests to a cloud endpoint.
What features were missing?
Better documentation for the GB10 memory architecture and llama.cpp flag compatibility. We had to experiment to find the right n-gpu-layers 99 and quantization format. A curated list of validated model/quantization/flag combos for the specific chip would have saved 2-3 hours on day one.
Do you find value in building on an edge device for local inference?
Yes. Our entire demo closes with pulling the ethernet cable out. Every building biography, every historical narration, every photo lookup runs on local SSD and local inference. For cultural infrastructure, that's not a feature, it's the point. Institutions (libraries, museums, city agencies) won't send their archival data to a cloud LLM. Local inference is the only path to adoption for that audience.
Any other final thoughts?
The $3,000 price point makes this a legitimate alternative to cloud inference budgets for small teams. We burned zero API credits across a 48-hour hackathon running a 30B model. That math works for startups and researchers, not just enterprises.
